# Backup and restore

Invoices are legal records: back up the database **and** the documents, and rehearse restores.

## What is backed up

| Data | Where | Tool |
|---|---|---|
| Database (all records, issued representations, audit, compliance records) | `postgres` service | `pg_dump --format=custom` |
| Documents (PDFs) | `documents` volume | `tar` |

PDFs can be regenerated byte-for-byte from the issued representations, but backing them up avoids relying on that.

## Docker Compose

From `deploy/`, with the stack running:

```bash
bash scripts/backup.sh ./backups
```

This writes `raccord-db-<stamp>.dump`, `raccord-documents-<stamp>.tgz` and a `.sha256` file. Copy them off the host (encrypted) and schedule the script (for example nightly via cron). `deploy/backups*/` is git-ignored.

### Restore

```bash
bash scripts/restore.sh ./backups <stamp>
```

The script verifies checksums, stops `web`, recreates the database schema from the dump (which also restores the append-only triggers), restores the documents, and starts `web`.

### Rehearsal (performed 2026-10-06)

1. Issued `F2026-00001` in a running stack; took a backup.
2. Started a second, empty stack (`COMPOSE_PROJECT_NAME=raccordrestore`, another port) and restored into it.
3. Verified: same invoice number and content fingerprint, byte-identical PDF, same audit events, and `DELETE FROM audit_events` refused by the trigger.

Repeat this rehearsal after every major upgrade.

## Azure

- PostgreSQL Flexible Server keeps automated backups for 14 days (point-in-time restore); raise retention for production.
- Blob soft delete (30 days) and versioning are enabled for documents.
- For long-term retention, export with `pg_dump` and copy the container with AzCopy to a separate, immutable storage account.

## Retention

Spanish rules require keeping invoices and records for years; confirm the period with your advisor (open question in `CHG-INITIAL`) and size retention accordingly.
