# 7. Deployment view

All paths use the same container image built by `deploy/docker/Dockerfile` (ADR-0013).

## Docker Compose (self-hosting)

```text
host
├── postgres (postgres:17-alpine)       volume postgres-data
├── migrate  (raccord image, "migrate") runs once, exits 0
└── web      (raccord image)            port ${RACCORD_HTTP_PORT:-8080} → 8080, volume documents
```

Configuration: `deploy/.env` (from `.env.example`). The host-side backup and restore tooling owns the database dump, document volume archive, checksum manifest and configurable retention; the backup set is external to the running containers. Operations: [self-hosting](../../operations/self-hosting.md), [backup and restore](../../operations/backup-and-restore.md). Put a TLS-terminating reverse proxy in front for anything beyond a trusted LAN.

## .NET Aspire (development)

`dotnet run --project src/root/Raccord.Aspire`: PostgreSQL (volume), Azurite (volume), `migrations` resource, `web` (API) and `frontend` (Vite with proxy). Dashboard with logs, traces and metrics. See [local development](../../operations/local-development.md).

## Azure (Bicep)

```text
Resource group
├── Container Apps environment ── Log Analytics
│   ├── Container App ca-raccord-<env>  (1 replica, ingress HTTPS, probes /health/live, /health/ready)
│   └── Container Apps Job caj-raccord-migrate-<env> (manual, args: migrate)
├── User-assigned managed identity ── Key Vault Secrets User, Storage Blob Data Contributor
├── Key Vault (RBAC, purge protection) ── secret: database connection string
├── PostgreSQL Flexible Server 17 (B1ms, 14-day backups) ── database raccord
└── Storage account (ZRS, no shared key, no public blobs, soft delete, versioning) ── container documents
```

See [Azure deployment](../../operations/azure-deployment.md).

## Public engineering snapshots

The repository's GitHub Pages site serves a generated arc42 snapshot, the ProductShape model snapshot, and nightly Playwright reports. The publisher is serialized; architecture and model pages refresh only when their respective source paths change, while the latest E2E report is generated by the nightly workflow. Reports contain fictional seeded data and browser recordings and are public. See [nightly E2E reports](../../operations/nightly-e2e-reports.md) and [ADR-0024](../../adr/0024-publish-static-engineering-snapshots-on-github-pages.md).
